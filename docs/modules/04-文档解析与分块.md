# 文档解析与分块开发规范

本模块负责把原始企业文档解析成结构化文本，再生成可检索、可引用、可回溯的 chunks。

## 模块职责

- Parser Registry。
- Docling adapter。
- MinerU adapter。
- Markdown/plain-text fallback parser。
- Structured chunker。
- Semantic chunker。
- Parent-child chunk builder。
- Contextual Retrieval prefix generator。

## Parser 接口

```python
class Parser:
    supported_types: set[str]

    async def parse(self, document: Document) -> ParsedDocument:
        ...
```

`ParsedDocument` 必须包含：

- `document_id`
- `source_name`
- `title`
- `blocks`
- `pages`
- `tables`
- `images`
- `metadata`

## Block 类型

- `heading`
- `paragraph`
- `table`
- `list`
- `image_caption`
- `code`
- `page_break`

每个 block 必须保留：

- `block_id`
- `text`
- `page_number`
- `heading_path`
- `order_index`
- `source_bbox` 可选

## Chunking 规则

- parent chunk 按章节、标题、表格或业务段落创建。
- child chunk 目标长度 200-500 tokens。
- 表格 chunk 必须保留表头、行组和前后说明。
- chunk 必须有 `parent_id`、`heading_path`、`page_numbers`。
- contextual prefix 不替代原文，只作为检索增强字段。

## Contextual Prefix 规则

前缀包含：

- 文档名
- 章节路径
- 业务对象
- 时间或制度范围
- 片段主题

禁止在 prefix 中编造原文不存在的事实。

## 不做什么

- V1 不强制 OCR 全格式完备。
- 不把 parser 输出直接塞给 LLM。
- 不让 chunk 丢失原始 source mapping。

## 测试要求

- `test_markdown_parser_preserves_heading_path`
- `test_docling_adapter_maps_tables_to_blocks`
- `test_chunker_creates_parent_child_relationship`
- `test_table_chunk_keeps_header_context`
- `test_contextual_prefix_uses_source_metadata`
- `test_chunk_page_numbers_are_preserved`

## 验收标准

- 同一文档重复解析和分块结果稳定。
- citation 能定位到文档、章节和页码。
- chunk 输出可直接进入 embedding、BM25 和 answer citation。
