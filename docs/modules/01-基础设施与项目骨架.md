# 基础设施与项目骨架开发规范

当前状态（2026-05-31）：已补充 `docker-compose.yml`、`.env.example`、`app/config.py`、full/fallback health 探测和基础设施单测。当前验证 `python -m pytest tests/unit/test_infrastructure.py tests/api/test_api.py -q -p no:cacheprovider` 为 17 passed；全量后端基线为 166 passed。下一步需要在普通 PowerShell 中启动 Docker 中间件并回传 `docker compose ps`。

本模块负责项目目录、配置系统、本地运行方式和基础设施连接。目标是让项目能在 full mode 使用 Docker Compose，也能在 test mode 不依赖外部服务运行核心测试。

## 模块职责

- 创建后端、前端、脚本、测试和文档目录结构。
- 管理 `.env`、`.env.example`、settings 和依赖注入。
- 提供 PostgreSQL、Redis、Milvus、Elasticsearch、MinIO、Phoenix 的连接边界。
- 提供 `GET /health` 健康检查。
- 定义 full mode 与 fallback mode。

## 不做什么

- 不在基础设施模块写业务逻辑。
- 不在 health check 中触发自动建表、自动迁移或数据写入。
- 不把 Docker 启动作为单元测试前置条件。

## 配置规范

`config.py` 使用 `pydantic-settings`：

- `ENVIRONMENT`: `dev | test | prod`
- `APP_MODE`: `fallback | full`
- `POSTGRES_URL`
- `REDIS_URL`
- `MILVUS_HOST`
- `MILVUS_PORT`
- `ES_URL`
- `MINIO_ENDPOINT`
- `MINIO_ACCESS_KEY`
- `MINIO_SECRET_KEY`
- `MINIO_BUCKET`
- `QWEN_API_KEY`
- `QWEN_EMBEDDING_MODEL`
- `QWEN_RERANK_MODEL`
- `EMBEDDING_DIM`
- `PHOENIX_ENDPOINT`

`test` 环境默认使用 fallback，不访问真实服务。

## Health Check 规范

`GET /health` 返回：

```json
{
  "status": "healthy",
  "mode": "fallback",
  "services": {
    "postgres": {"status": "skipped"},
    "redis": {"status": "skipped"},
    "milvus": {"status": "skipped"},
    "elasticsearch": {"status": "skipped"},
    "minio": {"status": "skipped"}
  }
}
```

full mode 下每个服务返回 `up | down` 和 `latency_ms`。

## 测试要求

- `test_health_marks_down_service_when_connection_fails`

## 验收标准

- `python -m pytest tests/test_health.py` 不依赖 Docker。
- `.env.example` 不包含真实密钥。
- full mode 的连接错误不会导致 API 进程启动失败，只会在 health 中显示 `down`。
