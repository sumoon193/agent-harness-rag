# 文档上传与异步入库开发规范

本模块负责接收企业文档、保存原始文件、创建入库任务，并通过异步流水线推进解析、分块、向量化和索引构建。

## 模块职责

- `POST /documents` 上传文件。
- 保存原始文件到 MinIO 或本地 fallback storage。
- 创建 `Document` 和 `IngestionTask`。
- 使用 Celery 编排异步任务。
- 提供任务状态查询和 SSE 进度推送。

## 输入输出

上传输入：

- `file`
- `departments`
- `visibility`
- `tags`
- `tenant_id`

上传响应：

```json
{
  "document_id": "doc_xxx",
  "task_id": "ing_xxx",
  "status": "queued"
}
```

任务状态响应：

```json
{
  "task_id": "ing_xxx",
  "document_id": "doc_xxx",
  "status": "indexing",
  "current_stage": "write_milvus",
  "progress": 0.7,
  "error": null
}
```

## 任务链

```text
upload
  -> parse_task
  -> clean_task
  -> chunk_task
  -> contextualize_task
  -> embed_task
  -> index_task
  -> mark_ready_task
```

每个 task 必须：

- 接收 `task_id` 和 `document_id`。
- 记录开始、结束、耗时、错误。
- 可单阶段重试。
- 保证重复执行不产生重复 chunk 或重复索引。

## Storage 规范

full mode：

- MinIO 保存原始文件和解析产物。

fallback mode：

- 本地 `storage/` 保存文件。

统一接口：

- `put_object(key, bytes, content_type)`
- `get_object(key)`
- `object_exists(key)`
- `delete_object(key)`

## 不做什么

- 上传接口不直接解析大文件。
- 入库失败不删除原始文件。
- 任务失败不吞异常，必须写入 `error_code` 和 `error_message`。

## 测试要求

- `test_upload_creates_document_and_task`
- `test_upload_rejects_unsupported_extension`
- `test_ingestion_status_updates_stage_progress`
- `test_failed_task_records_error_message`
- `test_retry_single_stage_does_not_duplicate_chunks`

## 验收标准

- 上传接口 1 秒内返回任务 ID。
- 任务状态能表达 queued、running、failed、ready。
- fallback mode 下不需要 MinIO 和 Celery 也能跑通同步入库测试。
