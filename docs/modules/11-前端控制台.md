- `npm run test:e2e`：5 passed，覆盖上传入库状态、Agent Run/SSE、Approve/Edit/Reject、citations 面板、trace 顺序。
- `python -m pytest -q -p no:cacheprovider`：166 passed，1 个 FastAPI TestClient deprecation warning。
- `python scripts/quality_gate.py`：全部通过。

本模块负责构建面试可演示的企业知识任务 Agent 控制台。

## 产品定位

前端不是营销页，而是操作型控制台。第一屏应直接展示文档、Agent 对话、审批和 evidence，而不是大 hero 区。

## 页面结构

- 文档入库页。
- Agent 控制台。
- 工具审批面板。
- Evidence citations 面板。
- Run trace 面板。
- Eval result 页面。

## 核心交互

标准 demo：

1. 上传 HR 制度文档。
2. 输入“新员工入职到转正要办哪些事项？”。
3. 右侧显示 evidence citations。
4. 中间显示 Agent plan。
5. 写入型工具出现 approval card。
6. 用户 Approve / Edit / Reject。
7. 显示 mock ticket result。
8. Trace 面板展示完整 step tree。

## API Client

前端必须封装 typed API client：

- `uploadDocument`
- `getIngestionTask`
- `createAgentRun`
- `getAgentRun`
- `streamAgentRun`
- `submitApproval`
- `runEval`

## UI 规范

- 使用企业控制台风格，信息密度适中。
- 用 tabs 切换 evidence、trace、eval。
- 审批按钮必须清晰区分 Approve、Edit、Reject。
- citation 不混在答案正文里，单独展示来源、章节、页码和分数。
- 对运行中、等待审批、失败、完成都有明确状态。

## 不做什么

- 不做营销 landing page。
- 不在前端编码权限规则。
- 不让前端伪造工具执行结果。

## 测试要求

- `upload page renders ingestion status`
- `agent console streams run steps`
- `approval card blocks tool execution until decision`
- `citations panel shows source section score`
- `trace panel renders ordered steps`

## 验收标准

- 面试演示能在一个页面解释 Agent Harness + RAG。
- 用户能清楚看到“证据、计划、审批、工具、trace”的关系。
- 移动和桌面宽度下无明显文本重叠。
