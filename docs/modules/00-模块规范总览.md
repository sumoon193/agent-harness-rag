# 模块开发规范总览

这份文档用于说明 `docs/modules/` 下各模块规范的阅读顺序、共同约束和验收口径。后续开发前应先读本文件，再进入具体模块规范。

编码实现标准见 `docs/CODING_STANDARDS.md`（命名、类型注解、异常、日志、测试、Adapter/Fake 等）。

## 项目主线

EnterpriseMind Agent Runtime 的核心架构是：

- **RAG 证据层**：负责文档入库、解析、分块、索引、检索、重排、引用和评测。
- **Agent Harness 治理层**：负责 Agent Run 生命周期、工具注册、审批、状态恢复、权限、审计和 trace。
- **Runtime Kernel**：负责长期 Case、Event Store、Outbox、Projection、Lease、SideEffect Ledger 和 Durable Timer。

项目不是普通 RAG Chatbot。任何模块设计都必须能回答：

1. 这个模块如何服务可信 evidence？
2. 这个模块如何服务可控 Agent Run？
3. 这个模块如何被测试、追踪和回滚？

## 通用开发约束

- 先实现纯 Python / in-memory / deterministic fake，再接真实外部依赖。
- 每个模块必须有单元测试；外部 adapter 必须有 fake 或 mock。
- 写入型操作必须支持幂等、防重复执行和审计记录。
- 所有用户可见回答必须能追溯到 citations 或明确说明证据不足。
- ACL 必须在检索前生效，生成答案前二次校验。
- 配置通过环境变量注入，不允许硬编码 API key、数据库密码和模型密钥。

## 文档命名规则

模块规范文件使用中文名，代码目录和模块名使用英文：

```text
docs/modules/05-索引与混合检索.md
app/services/retrieval/
```

## 每个模块的交付要求

每个模块完成时必须提供：

- 清晰的 public interface。
- 可运行的单元测试。
- 关键失败路径测试。
- 与上游、下游模块的数据契约。
- 日志或 trace 字段。
- 明确的“不做什么”。

## 横切模块

- API 层只负责协议适配和服务编排，不能承载领域决策。
- 测试与质量门禁贯穿所有模块，任何模块进入下一阶段前都必须有可复现验证命令。
